the first thing your agents need is a control plane

every coding agent gets more useful when it knows what it is allowed to do, what proof it owes, and when it needs to come back to me.

every coding agent i use eventually runs into the same boring problem: it can make a change, but it needs a system around it for responsibility.

that is what i mean by a control plane. for anipotts.com, that has been admin.anipotts.com: read-only first, content review second, guarded writes later. the live buttons come after the state model is boring and obvious.

the spine is simple: intent -> authority -> operation -> proof -> state.

safe lanes versus hard gates

i want agents to move quickly when the blast radius is small. if the lane is safe, the agent should inspect, edit, verify, commit, push, and open a PR without waiting on me.

other work needs a hard gate. dns, auth, secrets, env, production content, outbound sends, live endpoints, payments, and destructive cleanup all need explicit authority. the point of the control plane is to make that split visible before the agent touches the thing.

proof beats trust

a finished agent task should leave proof another agent can inspect. that can be a commit, a PR, a command result, a deploy record, a screenshot, or a blocked-action list. the important part is that it survives the chat.

once multiple agents are touching the same repo, the durable object matters more than the explanation. the next agent should continue from the artifact instead of guessing what happened in the previous conversation.

NEEDS-ANI is the human syscall queue

the human queue should be tiny. i do not want a dashboard full of agent homework. i want the few calls only i can make.

that means approval, choice, account-side action, identity, payment, secret setup, final taste, or a source-delete call. routine status belongs in commits, PRs, handoffs, and proof records.

admin is the control plane

this is why admin.anipotts.com starts read-only. i need one place where content, fleet state, handoffs, approvals, and proof are legible.

the order matters. read-only first. preview second. guarded writes after the authority model is real. live controls come after the foundation.

working close

the version of this i want is boring in the best way. agents know what they can do next, what proof they owe, and when the right move is to return one clear decision to me.
