the first thing your agents need is a control plane

a practical note from building admin.anipotts.com as a read-only operator dashboard first, then a content review surface, then a guarded write path.

note

safe lanes versus hard gates

start with the contract. some work is safe to finish end to end: inspect, edit, verify, commit, push, and open a draft PR. other work is gated because it touches live systems, secrets, auth, DNS, publishing, outbound sends, or irreversible state. the contract makes the next allowed move obvious.

the useful split is allowed operations versus gated operations.

receipt

proof beats trust

a finished agent task should leave proof that another agent can inspect: changed files, exact checks, commits, PRs, deploy evidence when deploys are authorized, and explicit blockers when they are not. trust is too vague for a shared repo. proof is portable.

proof lets the next agent continue the work without inheriting chat memory as a source of truth.

note

NEEDS-ANI as a human syscall queue

the human return path should be small. NEEDS-ANI has one job: agents ask for the few decisions only Ani can make, including approval, choice, secret setup, account-side action, identity, payment, or final taste.

a good human queue is narrow enough to answer from a phone.

worklog

admin as the control plane

admin.anipotts.com should make state legible before it makes state mutable. content, fleet state, handoffs, approvals, and proof belong in one surface because agents need to know what they are allowed to do next.

  • read-only operator dashboard first
  • content inventory and preview states next
  • guarded write paths only after authority exists
  • live gates visible before any live control exists

the control plane maps intent to authority to operation to proof to state.

close

the future looks like a system where agents know what they are allowed to do next, what proof they owe, and when the right move is to return one clear decision to Ani.
